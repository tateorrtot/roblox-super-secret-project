# The day the code was rewritten (2026-11-20)

The user reviewed the code three times in one day, and it was broken up, rewritten and renamed. Their words are in `docs/working/code-reviews/`, and the audit is `docs/code/reviews/15-code-double-check-2026-11-20.md`.

- **What changed in the code that day** (docs/code/reviews/15 records the audit that led to it):
  - **The rules no longer know about the mouse.** `InventorySession` (709 lines, with `click`, `doubleClick` and `drag`) is gone. `InventoryScreen` has operations named for what they do. Which operation a click, a double click or a drag asks for is decided on the player's machine, by `SlotGestures` (which gesture it was) and `InventoryControls` (what it asks for), and the request that is sent names the operation.
  - **A request is one small function that does what its name says.** `InventoryRequests.dropCarriedStack` puts the stack on the ground itself. `Requests` routes by name, and its names come from the functions, so the list is written once.
  - **`World` was nine jobs.** It is now the game's state, what can be done in it, and `advanceTo`. A player is one record, `PlayerState`. What a player's machine is told is `PlayerSnapshot`.
  - **Use and Hit have a piece of their own** on the player's machine, `UseAndHit`.
  - **Every file is written to the conventions** as rewritten that day, and the functions nothing called are deleted.
  - **Sixty-two public functions and three constants were renamed after the third review,** so that each says what it acts on and where, and then eleven fields and four more constants by the same rule (`screen.other` became `screen.otherInventory`, and `PACK_SLOTS` became `PACK_SLOT_COUNT`). `pickUp` became `pickUpFromSlot`, `moveStack` became `moveFromSlotToInventory`, `gather` became `fillCarriedStackFromAllSlots`, and "placed" became "placed item" everywhere. Two functions called `step` became `Station.advance` and `World.advanceTo`. `python tools/outline.py --names` prints the outline as it now stands.
- **Measured before and after** (`python tools/metrics.py`): `src` went from 6,197 lines to about 4,500. Comment lines went from 38% of the non-blank lines to 20%. Functions nesting three deep or more went from 10 to 0. The tests went from 1,566 checks to 1786.
- **The names were tested as the user tests them.** Four fresh readers (Sonnet, the `Explore` agent type) were given each file's first line and the bare names of its functions, and wrote what each takes and does. Two had the old names, as a control, and two the new. On the old names they stumbled where the user had: `accepts` was unclear to both and `gather` to one, and both read `moveStack` as "from one slot to another slot", which was the user's own wrong guess. On the new names both said correctly what every inventory operation does. What no name told them is how much moves and what comes back, which the signature says, and that a placed item is named by an id where they expected its tile. Their answers changed six of the proposed names before any was applied: `fillCarriedStackFromAllSlots` (they expected "FromSlots" to take a list), `slotAcceptsItem`, `hasEverySlot`, `dropFromSelectedSlot` (a name with "hand" in it read as the carried stack), `getFuelLeftRatio` and `getWorkDoneRatio` (they expected `getProgress` to return one number), and `setHighlightedSlots`. A fifth reader, given the names after those changes, read all six correctly and was left with five more questions, which changed five more names: `InventoryScreen.getInventoryOnSide` (which inventory?), `dropStackAt` on `World` and `GroundItems` (where does it land?), `GroundItems.moveNearbyStacksToInventory` (picked up into what?), `UseAndHit.startListening` and `PlaceholderWorld.addStartingItemsToPack`. **Those five have not been put to a reader.**
- **The play test passed 61 of 61 on the final code.** For some hours before that Claude had told the user that Studio was closed. It was open the whole time. `tools/studio.py` asked Studio's connector which Studios were attached as soon as the connector started, and Studio attaches two or three seconds later, so the answer was always empty. The tool now waits up to ten seconds. Do not report Studio as closed on that message alone: look for the `RobloxStudioBeta.exe` process.
